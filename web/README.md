# TermPocket — phone app (PWA)

Vanilla ES modules + CSS, no build step, no framework, no CDN. Served by the agent from `web/`
(or by the optional [relay](../docs/relay.md)) and talks to it over `wss://<host>/ws`
([PROTOCOL.md](../PROTOCOL.md) §3–§4, §6). What it does for users: [docs/user-guide.md](../docs/user-guide.md);
how it fits with the other parts: [docs/architecture.md](../docs/architecture.md).

`vendor/` is not in git: `npm install` (or `npm run vendor`) in `agent/` fills it with xterm.js and Monaco.
Edit the files in place and reload — there is nothing to build. Check your change with
`node web/tools/check-refs.mjs --strict`, and bump `VERSION` in `sw.js` when the list of app-shell files
changes.

## Behaviour notes (choices where the contract leaves room)

* **Rename (VS Control → TermPocket):** all saved state lives under `termpocket.*` localStorage keys. An inline
  script in `index.html` moves keys saved by the app before the rename (`vscontrol.*`: token, layout, …) to their
  new names once, before anything reads them; `sw.js` removes the old `vscontrol-*` caches and moves the old
  Monaco cache into the new one. The manifest `id` is unchanged, so an installed app updates in place.

* **Security:** every remote string is rendered via `textContent`/text nodes; the ANSI renderer
  builds spans with inline colour styles — no `innerHTML` with remote data anywhere.
* **Reconnect:** backoff 0.5 s → 15 s with jitter (60 s after close code 4429); close code 4401 or
  `bad token` stops retrying and shows the pairing screen. A cheap `pty.list` probe detects
  half-open sockets after 40 s of silence or when the app returns to the foreground.
  On reconnect the open terminal view re-attaches (`pty.attach`, screen reset + scrollback) and the
  screen stream restarts if the Screen tab is visible.
* **Terminal size:** agent-only PTYs auto-fit to the phone (`pty.resize`, debounced). PTYs mirrored
  in VS Code keep their PC size (horizontal scroll) until the user taps *Fit*, so opening one on the
  phone doesn't reflow the VS Code terminal. Sticky Ctrl/Alt: tap = next key, tap again = lock,
  third tap = off. Arrow/PgUp/PgDn keys auto-repeat on long-press.
* **Exec log** uses `terminals.exec` in *Run* mode and `terminals.sendText` in *Text* mode.
* **Editor** keeps CRLF files CRLF on save and refuses to save truncated (> 2 MB) files.
* **Screen:** only the newest queued frame is drawn; every frame is acked (`screen.ack`) right after
  it is drawn or skipped, so the agent's ≤ 2-in-flight flow control never stalls. Streaming stops
  when the tab is hidden, the app goes to the background, or the user pauses.
  Touch mode: tap = click, double-tap = double-click, long-press = right-click, long-press + drag =
  left-drag, two-finger vertical drag = scroll, pinch = zoom, one-finger drag while zoomed = pan.
  Trackpad mode: drag moves a pointer, tap = click, two-finger tap = right-click.
* **Service worker:** cache-first, refreshed in the background (stale-while-revalidate) so agent
  updates show up on the next launch even without a `VERSION` bump. `/ws`, `/vscode`, `/healthz`
  and `/pair` are never intercepted. Registered only in secure contexts (`https://…ts.net` via
  `tailscale serve`, or `localhost`).
* Android back button closes the top-most sheet/dialog/full-screen view (history-based layer stack).

## Desktop browser (v0.2, PROTOCOL §8.3)

* **Layout switch:** `js/layout.js` decides with `matchMedia('(min-width: 900px) and (pointer: fine)')`
  and sets `html.desk` (an inline script in `index.html` applies the same rule before first paint). All
  desktop CSS hangs off `html.desk`, so CSS and JS never disagree. Menu → Settings → Layout can force
  Desktop (still needs ≥ 900 px) or Phone. Below 900 px / touch-only devices the phone UI is unchanged
  (`.sidebar` is `display: contents` there, so the top bar and bottom tab bar are laid out as before).
* **Shell:** left sidebar = brand, vertical nav with badges, footer card with host + connection state
  (click = retry / menu) and a settings button. Sheets become centred dialogs; toasts go bottom-right.
* **Terminals:** session list left (resizable), tabs right. Every tab is its own `openTermView` embedded
  in a pane (`openView(…, {embed})`), kept alive while hidden, so all open terminals keep receiving
  output. A hidden pane is never fitted (no 0×0 `pty.resize`). Ctrl+Shift+T = new terminal with the last
  shell/folder, Ctrl+Tab cycles tabs, middle-click / × closes a tab (detach — the shell keeps running,
  kill it from the list). Physical keyboard goes straight into xterm; Ctrl+C copies when text is
  selected, Ctrl+V pastes. Extra-keys row and command line are hidden by default (header toggle / menu).
  Ctrl+Shift+T / Ctrl+Tab are reserved by Chrome in a normal tab; they work in the installed app window.
* **Code:** explorer left; editor tabs right (unsaved dot, closing a dirty tab asks); Open editors /
  Problems / Commands in a resizable, collapsible bottom panel. Opening a problem jumps to its line in
  the already-open tab. "Terminal here" opens a tab in the Terminals split view.
* **System:** card row + two columns (power / clipboard / open-on-PC left, processes right).
* **Screen:** large canvas, HD preset (10 fps / q 65 / 1920 px — desktop only), "All displays"
  (monitor −1, falls back to the primary display with a notice when the agent rejects it), the PC's
  pointer drawn from `screen.meta` (also meta-only updates), latency in the stats line.
* **Remote Desktop** (`js/rdp.js`; button, More menu, or Ctrl+Alt+Enter on the Screen tab):
  `requestFullscreen` on `<html>` + `navigator.keyboard.lock()`; the Screen tab is `position: fixed` over
  the app (sheets / popovers / toasts stay on top). If fullscreen is refused it still works "windowed".
  - mouse: pointermove → `input.mouse move` ≤ 30/s, coalesced, ≤ 2 in flight; buttons by diffing
    `PointerEvent.buttons` (so chorded buttons work) → `down`/`up` (left/right/middle); the OS builds
    double-clicks; presses on the letterbox bars are ignored; context menu / middle-click autoscroll off.
  - wheel: pixel deltas (lines × 40 px, pages × view height) accumulate, 120 px = 1 notch, both axes
    (`delta`, `deltaX`), remainder reset after 600 ms or a direction change. A classic wheel event
    (`wheelDelta` a multiple of 120, |delta| ≥ 50 px) counts as whole notches immediately, so Chrome's
    100 px-per-notch never swallows the first notch.
  - keyboard: every keydown/keyup → `input.keyraw {code, down}` + `preventDefault` (auto-repeat sends
    more key-downs). If the agent answers "unknown method" it falls back to `input.key` / `input.text`
    once and says so. Ctrl+Alt+Break leaves Remote Desktop (never sent to the PC); with keyboard lock,
    hold Esc to leave fullscreen (Chrome), which also leaves the mode.
  - `input.releaseAll` on window blur, tab hidden and exit (fallback: release the held keys/buttons).
  - view: Fit (letterbox) / Fit width / 1:1 device pixels; when the picture is larger than the window,
    keeping the pointer at an edge pans it. Coordinates always come from the canvas' on-screen rect.
  - clipboard sync (Settings, default on, secure context only): on focus, local text ≠ last synced →
    `clip.set`; 300 ms after Ctrl+C / Ctrl+X → `clip.get` → `navigator.clipboard.writeText`. A denied
    permission disables the automatic read until re-enabled; toolbar "To PC" / "From PC" force it.
  - toolbar (auto-hides; move to the top edge or pin it): Exit, display, quality (Low/Med/High/HD,
    remembered separately for Remote Desktop, default HD), view, Task Manager (Ctrl+Shift+Esc as a
    keyraw sequence — Ctrl+Alt+Del can't be injected), Win, Alt+Tab, clipboard, live fps · KB/s ·
    latency, keyboard-lock state (Keys locked / Esc exits / Windowed), settings.

## Desktop Code tab: the VS Code workbench (`js/wb/`)

On the desktop layout the Code tab is a VS Code workbench (Dark Modern) for one VS Code window at a time
(title-bar window switcher; per window its own editor tabs, expanded folders, and the tabs come back after a
reload). The phone layout keeps the classic Code tab; switching layouts live swaps them. Without
`vendor/monaco` (agent not installed with `npm install`) the classic desktop split view is used instead.

* **Editor:** Monaco (VS Code's editor component), loaded lazily with its AMD loader from
  `vendor/monaco/vs` (runtime-cached by `sw.js`, never pre-cached). Only the base editor worker runs:
  Monaco's own TS/JSON/CSS/HTML validation and language workers are off, the squiggles are VS Code's
  diagnostics (`diagnostics.list`, refreshed on `diagnostics.changed`). Ctrl+S = `fs.write` after a fresh
  `fs.read` (changed on the PC since it was loaded → "Overwrite?" dialog). Preview tabs (italic, replaced by
  the next single-click open; double-click or editing pins), dirty dot, middle-click close, Ctrl+W,
  Ctrl+Tab (most recently used), Ctrl+PageUp/Down, drag to reorder, breadcrumbs with folder pickers, diff
  editor vs HEAD (`git.show`), "Follow PC" (opens what VS Code shows), Alt+Left/Right history.
* **Explorer:** lazy `fs.list` tree with VS Code keyboard navigation, inline New File / New Folder / Rename
  (F2), Delete (Recycle Bin, confirmed), Copy Path, Reveal in File Explorer / Open in VS Code on the PC,
  problems and Git decorations, auto-reveal of the active file, VS Code's default `files.exclude`.
* **Shell API** (`createWorkbench(rootEl, app)` → `wb`): `activity`, `panel`, `status`, `commands`, `keys`,
  `editors`, `quickInput` / `setQuickInput`, `call`, `onVsc`, `onWindowChange`. Optional modules
  `js/wb/<name>.js` (`C_MODULES` in shell.js: palette, statusbar, problems, panel, wbterminal, scm, search)
  export `register(wb)` (idempotent) and are loaded at start-up; a missing or failing one is skipped and the
  shell falls back to a minimal palette / status bar. `tools/check-refs.mjs` follows `C_MODULES` like imports.
* **Never stuck loading:** every view ends in data, an empty message, or an error with *Retry*; calls carry
  deadlines (15 s in the panel / palette / SCM / search modules, `conn.vsc` 35 s, the extension answers
  within 20–25 s). The phone Code tab drops answers for a previous window or a superseded request
  (`filesSeq` / `cmdSeq`) instead of leaving their spinner behind.
* **Keys:** the workbench takes shortcuts while it is visible and the focus is inside it, on the page body,
  or on the app's own nav (after clicking the Code tab Ctrl+P works at once).
* Shortcuts work in the installed app window; in a normal browser tab Chrome keeps Ctrl+W, Ctrl+Tab,
  Ctrl+PageUp/Down and Ctrl+Shift+T for itself.
